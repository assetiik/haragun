# Контракт Flutter: наличие / «Нет в наличии»

Бэкенд отдаёт остаток по товару. Фронт затемняет карточку и показывает «Нет в наличии», когда товара нет.

## Поля в меню и карточке товара

Есть в:

- `GET /api/establishments/{id}/menu` → `products[]`, `featured`
- `GET /api/establishments/{id}/menu/products/{productId}`
- `GET /api/establishments/{id}/foodcourt` → товары секций

```json
{
  "id": 12,
  "name": "Круассан",
  "stock_quantity": 0,
  "in_stock": false
}
```

| Поле | Тип | Смысл |
| --- | --- | --- |
| `in_stock` | `bool` | Можно заказывать. `false` → затемнить + «Нет в наличии» |
| `stock_quantity` | `int \| null` | Остаток. `null` = без лимита (всегда в наличии, пока `in_stock: true`) |

Примеры:

```json
{ "stock_quantity": null, "in_stock": true }
{ "stock_quantity": 5, "in_stock": true }
{ "stock_quantity": 0, "in_stock": false }
```

Товар с `in_stock: false` **остаётся в списке** — не скрывайте его, только дизейблите.

## UI

- `in_stock === false` → затемнить карточку / кнопку, текст «Нет в наличии», не открывать добавление в корзину
- `in_stock === true` → обычное поведение
- `stock_quantity` можно показать как «Осталось N», если не `null` и хотите; для MVP достаточно `in_stock`

## Корзина

Бэкенд тоже режет:

- добавить товар с `in_stock: false` → `422` на `product_id`: «Нет в наличии.»
- quantity больше остатка → `422` на `quantity`: «Доступно только N шт.»

Клиенту всё равно лучше блокировать UI заранее по `in_stock`.

## Админка

У напитка / еды поле **Остаток**:

- пусто = без лимита
- `0` = нет в наличии
- `> 0` = сколько штук доступно

Автосписания при заказе пока нет — остаток меняет админ (или позже подключим).
