# Контракт: логин по SMS (OTP)

Для Flutter. Код приходит реальной SMS через Mobizon. Эндпоинты те же — меняется только источник кода.

## Что менять, а что нет

Не трогать:

- пути `/api/auth/*`
- формат `phone` / `code`
- сохранение Bearer после verify
- экран имени при `needs_name: true`

Сделать / проверить:

1. Не опираться на `debug_code` в проде — его нет
2. Показывать ошибку, если `send-code` вернул не 200 (SMS не ушла)
3. Таймер повторной отправки ≥ 60 сек (на бэке throttle 5 req/min)

## Телефон

Перед отправкой нормализуй к `7XXXXXXXXXX` (11 цифр, начинается с `7`).

Бэкенд сам чистит пробелы/`+`/`()` и `8XXXXXXXXXX` → `7…`. Можно слать и так:

```json
{ "phone": "+7 (778) 404-68-89" }
```

или уже нормализованный:

```json
{ "phone": "77784046889" }
```

Неверный формат → `422` на поле `phone`.

## Отправить код

```http
POST /api/auth/send-code
Content-Type: application/json

{ "phone": "77784046889" }
```

Успех `200`:

```json
{
  "sent": true
}
```

На **не-production** может быть ещё поле:

```json
{
  "sent": true,
  "debug_code": "4821"
}
```

- В **production** `debug_code` нет — код только в SMS
- SMS текст: `Ваш код для входа в Haragun: {code}`
- Код: 4 цифры, живёт **5 минут**
- Throttle: **5 запросов / минуту** на IP → при превышении `429`

Ошибка SMS-шлюза → `502`:

```json
{
  "message": "…"
}
```

В этом случае OTP не считается доставленным: покажи «Не удалось отправить SMS, попробуйте ещё раз».

## Подтвердить код

```http
POST /api/auth/verify-code
Content-Type: application/json

{
  "phone": "77784046889",
  "code": "4821"
}
```

`code` — ровно 4 цифры.

Успех `200`:

```json
{
  "token": "1|…",
  "token_type": "Bearer",
  "user": {
    "id": 1,
    "name": null,
    "phone": "77784046889",
    "needs_name": true,
    "notifications_enabled": true
  },
  "needs_name": true
}
```

Дальше все запросы:

```http
Authorization: Bearer {token}
```

Если `needs_name: true` — сразу экран ввода имени (как раньше).

Неверный / просроченный код → `422`:

```json
{
  "message": "Неверный или просроченный код",
  "errors": {
    "code": ["Неверный или просроченный код"]
  }
}
```

Throttle verify: **10 / минуту**.

## Выход / удаление

Без изменений:

```http
POST /api/auth/logout
Authorization: Bearer {token}
→ 204

DELETE /api/auth/account
Authorization: Bearer {token}
→ 204
```

После удаления тот же номер может зарегистрироваться заново (`needs_name: true`).

## UX-чеклист

1. Экран телефона → `send-code` → экран кода
2. Пока ждём SMS: индикатор + возможность resend через ≥ 60 сек
3. 4 ячейки / поле под цифры, автосабмит при 4 символах
4. На ошибке `422` по `code` — тряска / подсветка, не выкидывать с экрана
5. На `502` / сети — тост и кнопка «Отправить снова»
6. `debug_code` можно подставлять только в debug/staging сборках, в release игнор

## Локальная отладка бэка

Если на сервере задан `OTP_STATIC_CODE=1234`, SMS не шлётся и код всегда `1234`.  
На проде и на нормальном staging переменная пустая — только SMS.
