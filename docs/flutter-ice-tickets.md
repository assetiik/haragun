# Контракт: билеты на каток и QR на турникет

Для Flutter. Checkout не ломаем: дата, время и `product_id` как сейчас. Новое — экран QR из `passes`.

DSS (турникеты) подключается на бэкенде. Приложению не нужны токен, PEM, show id, day id, slot id.

## Что менять, а что нет

Не трогать:

- логин
- кофе / фудкорт / корзина
- `POST /api/orders` тело запроса
- список заказов, кроме перехода в детали билета

Сделать один раз:

1. Экран QR по `order.passes[]`
2. Игнорировать неизвестные поля в JSON (`dss_day_id`, `ends_at`, `entry_opens_at`, `passes`)
3. Опционально: после выбора слота перезапросить меню с `time`, чтобы цена была актуальной

Если это сделать, второй раз контракт билетов менять не планируем. Refresh QR / статус «уже прошёл» — только если DSS потом отдаст API, это отдельный пункт.

## Расписание арены

`GET /api/establishments/{id}?category=ice_rental&date=2026-02-13`

Как сейчас, плюс поля, которые можно не использовать:

```json
{
  "selected_date": "2026-02-13",
  "dates": [
    {
      "date": "2026-02-13",
      "weekday": 5,
      "day": 13,
      "is_available": true,
      "dss_day_id": 10
    }
  ],
  "slots": [
    {
      "time": "16:00",
      "ends_at": "17:00",
      "is_available": true,
      "dss_slot_id": 3
    }
  ],
  "products": [
    { "id": 1, "kind": "ticket", "name": "Взрослый", "price": 2500 }
  ]
}
```

- Показывать `dates[].date` и `slots[].time`, как сейчас.
- `dss_*` не слать на бэкенд.
- `ends_at` можно показать как «16:00–17:00». Если поля нет (старый ответ) — сеанс 60 минут.
- Пока DSS не привязал событие, дат может быть 30 штук без `dss_day_id`. Это нормально, checkout тот же.

Цена слота (когда DSS включён):

`GET /api/establishments/{id}?category=ice_rental&date=2026-02-13&time=16:00`

Без `time` цена может быть локальной. С `time` — цена этого сеанса.

## Покупка

Как сейчас. Auth: Bearer.

```http
POST /api/orders
```

```json
{
  "establishment_id": 1,
  "date": "2026-02-13",
  "time": "16:00",
  "items": [
    { "product_id": 11, "quantity": 2 },
    { "product_id": 12, "sizes": [38, 41] },
    { "product_id": 13, "quantity": 1 }
  ]
}
```

Ответ `201`: `{ "order": { ... } }` — тот же объект, что `GET /api/orders/{id}`.

Ошибка билетной системы: `422` или `502`, поле `message`. Не ретраить checkout сам: бронь 30 минут живёт на бэкенде.

## QR — единственный новый экран

`GET /api/orders/{id}`  
`primary_action` в списке по-прежнему `booking_code`. Открывать детали и рисовать QR из `passes`.

```json
{
  "id": 50,
  "type": "tickets",
  "status": "confirmed",
  "code": "HRG-4821",
  "session": {
    "date": "2026-02-13",
    "time": "16:00",
    "ends_at": "17:00",
    "entry_opens_at": "15:00"
  },
  "passes": [
    {
      "id": "10-0",
      "item_id": 10,
      "label": "Взрослый",
      "barcode": "QR-ADULT-1",
      "valid_from": "2026-02-13T15:00:00+00:00",
      "valid_until": "2026-02-13T17:00:00+00:00",
      "is_active": false
    },
    {
      "id": "10-1",
      "item_id": 10,
      "label": "Взрослый",
      "barcode": "QR-ADULT-2",
      "valid_from": "2026-02-13T15:00:00+00:00",
      "valid_until": "2026-02-13T17:00:00+00:00",
      "is_active": false
    }
  ]
}
```

Правила:

- Один человек = один элемент `passes` = один QR.
- В QR класть `barcode` как есть, без URL и префикса.
- Не брать `order.code` (`HRG-4821`) — турникет его не читает.
- Коньки и шлем в `passes` не входят.
- `barcode: null` — билет куплен, код ещё не выдан. Текст вроде «QR появится перед сеансом».
- `is_active: true` только если есть barcode и сейчас окно входа: за час до `session.time` до `session.ends_at`.
- До окна: «Вход откроется в {entry_opens_at}».
- После `ends_at`: билет недействителен.
- Скриншот одного QR друзьям бесполезен: код одноразовый на турникете.
- Яркость экрана на максимум, свайп между людьми.

Для кофе `passes` — `[]`.

## Список заказов

`GET /api/orders?type=tickets` без изменений. QR только в деталях.

## Пока DSS не отдал шоу

Checkout и слоты работают по-старому. `passes[].barcode` будет `null`. Экран QR всё равно лучше повесить: когда DSS включат, коды появятся без новой сборки приложения.
